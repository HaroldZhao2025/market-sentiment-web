# SLOAN / SHIFT — MIT Sloan 上班激励器

一个无第三方依赖、无网络请求、可离线运行的独立 HTML。下载 `index.html` 后，用允许 JavaScript 的现代浏览器打开；也可以随现有网站的静态资源一起部署。无需安装 Node、React 或任何依赖。

## 使用

默认单位为 **MIT Sloan**，月薪 **USD 5,000**，每周基准工时 **60 小时**。填入工作事项后点击「启动计时」，休息时点击「暂停计时」，下班点击「结束保存」。右上角可切换「终末地」与「宏山」主题。

计薪公式为：

```
时薪 = 月薪 × 12 ÷ 52 ÷ 每周工时
默认时薪 = 5000 × 12 ÷ 52 ÷ 60 = 19.23076923076923 USD/h
每秒折算收入 = 19.23076923076923 ÷ 3600 = 0.00534188034188 USD/s
```

按每年 52 周折算，不把一个月简单当作 4 周。金额主屏显示四位小数，内部计算不逐秒舍入。金额是激励用途的工时折算，不代表实际额外收入，也不计算税费、加班费、假期或工资发放规则。每次工作锁定开始时的费率；修改参数只影响下一次工作，不重算历史记录。

## 统计与修正

- 「本周累计」显示当前自然周的时长和折算收入。默认按纽约/波士顿时区、周一开始；可切换北京、巴拿马或 UTC。
- 周/月图表可以前后翻页，点击柱形查看当天收入与时长。当前周期可能尚未结束，对比文案明确使用上一完整周期。
- 以 UTC 时间戳保存工作时段，按选定时区进行日/周/月分摊。跨午夜、跨周、夏令时均按实际经过的时间计算。
- 记录列表只显示所选周期内的有效时长与收入；跨期记录在其他周期也会显示相应部分，修正时则编辑整条记录。
- 「补录工时」与「修正」支持多段有效时段，暂停不会被填回工作时间。重叠记录、结束早于开始、明显未来时间会被拒绝。
- 本地时区的夏令时重复小时不能通过新输入猜测；已有精确时间戳可原样保留，JSON 备份也保留时间戳。

## 计时语义

计时使用当前时间减去已保存的起点，而不是累加 `setInterval` 回调次数，因此页面进入后台不会因刷新节流而少算。

**未主动暂停/结束时，离开页面、关闭浏览器和设备休眠期间仍会计入工时。** 重新打开会按保存的时间戳恢复。连续运行超过 12 小时会提示检查。忘记停止时，请先结束保存，再用「修正」调整结束时间。设备系统时钟应保持准确。

## 保存、备份与隐私

运行记录存于当前浏览器的 `localStorage`，键为 `sloan-shift:v1`；没有账户系统、云同步、埋点、第三方字体、外部脚本或网络上传。代码公开包含用户要求的默认月薪 5,000，但使用过程中产生的工作记录不会提交 GitHub。

数据按浏览器存储空间隔离，而非跨设备共享。同一域名的其他可信/不可信脚本原则上可以访问同源 localStorage，因此这不是加密保险箱。GitHub Pages 同一账号下的项目可能共享 origin；请只在自己信任的站点环境使用。

更换浏览器、设备、网页地址来源或本地文件位置时，数据不一定共享。清理网站数据、无痕模式退出、浏览器存储回收可能导致记录丢失。请定期导出 **JSON** 备份；不要把浏览器存储当作唯一副本。

右上角「数据中心」支持：

1. **JSON 完整备份**：所有记录、参数、主题与当前工作快照，可以恢复。
2. **CSV 工时明细**：每个有效工作时段一行，包含 UTC、本地时间、时区、秒数、费率和收入。
3. **CSV 周/月日报**：当前所选周期逐日汇总，包含运行中的工作。
4. **导入 JSON**：校验后确认替换本地数据；替换前触发当前数据的备份下载，请保留该文件。不会静默合并并重复计数。

备份时不会暂停原页面，但备份副本内的当前工作会冻结为暂停状态，避免在另一设备恢复时把迁移间隔错误计为工作。所有 CSV 均含 UTF-8 BOM，文本公式前缀会被中和。备注按纯文本显示，不作为 HTML 执行。

若持久存储不可用，页面显式提示临时内存模式；关闭前请导出。若已有数据损坏，不会默默清空或覆盖，先导出原始数据，再恢复有效备份。

支持 Web Locks 的环境会串行处理跨标签页写入，并监听存储变更；不支持时使用同步读改写，建议仅开一个计时页面。没有跨设备并发协调。

## 部署说明

该目录位于 `apps/web/public/work-motivator/`，供现有 Next.js 静态导出保留。预期网站路径为 `/market-sentiment-web/work-motivator/index.html`。

**GitHub 文件提交不等于 GitHub Pages 已发布。** 仓库现有生产流程的 `push` 过滤器只包含其自身工作流文件，本次新增 HTML 不会单独触发该生产流程；需现有生产流程成功发布包含此目录的版本后，公开网址才可使用。本功能未修改、强制重启或替换原有行情部署。

本地直接使用不依赖部署。在手机上，文件管理器或聊天应用的 HTML 预览器可能不执行脚本；应通过真正的浏览器网页使用，或在电脑浏览器打开下载的 HTML。未做原生 Apple Health / HealthKit 集成。

## 验证记录

开发版本通过了 15 项 Node 核心计算测试和 36 项 Chromium DOM/交互检查，覆盖费率、暂停、跨日跨周、夏令时、序列化恢复、补录修正、重叠拒绝、JSON/CSV 导出导入、主题切换和 320/360/390/768/1440 像素视口。

重要限制：测试环境的 Chromium 管理策略不允许导航本地文件/本地 HTTP，因此 DOM 测试通过 `set_content` 加载页面，并使用注入的内存 Storage 适配器验证状态保存与恢复。它不等于真实浏览器的持久化、Safari/iOS 后台恢复或多标签 Web Locks 已经实机验证。计算核心测试使用真实 Intl 时区实现。

回归测试：在仓库根目录运行 `node --test tests/work-motivator.test.cjs`。测试从实际 HTML 中抽取计算脚本，避免另存一份核心代码造成偏离。
